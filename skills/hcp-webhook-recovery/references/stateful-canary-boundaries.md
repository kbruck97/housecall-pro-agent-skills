# Stateful integration canary boundaries

This reference preserves integration safety lessons; it does not authorize a live canary. Prefer offline synthetic tests. A later owner-authorized test must name exact tenant, recipient, records, runtime, permitted effects, rollback and evidence retention. No source-host commands or runtime tool names are universal.

## Distinct outcomes

Edge accepted → ingress durably recorded → queue projected → scanner eligible → deterministic consent/identity/owner gates cleared → provider accepted → terminal delivery callback. A public-form response saying delivered may mean only edge-to-ingress handoff. Preserve source receipt, tenant, lifecycle, classified intent, due state, hold reason, provider ID and callback status separately. Late classification is unknown until bounded readback observes it.

## Preflight

Verify current runtime/capability/flag identity without printing secrets. Read the deployment's actual board field IDs and every reference to the exact synthetic item; semantic names may not equal stored columns. Confirm records and recipient are owner-controlled. Back up mutable state consistently and hash the backup before an approved reset. Configuration rollback is distinct from data rollback. Do not clear DNC, duplicate-send suppression, terminal status or safety holds to manufacture success.

A representative ingress payload includes the real contract's stable submission ID, timestamp, source and consent fields. Keep classifier language representative; synthetic labels belong in non-classifier metadata where allowed. A held “authorized test” inquiry can be a correct ambiguous classification, not a reason to bypass the classifier. Every retry may also create office notifications. Any clean retry needs the same explicit effect scope and must stop on a second hold.

## Exact-record observation and execution

An authorized send harness must assert exact tenant, item, recipient, source event, eligibility, mode and approval. Use the real runner's lock, consent/owner checks, branding, ledgers and provider path—not a direct provider call that bypasses gates. A test allowlist is not expanded just to pass. Never launch a broad tenant sweep for an exact-record canary.

Malformed classifier output, ambiguous identity, office activity, DNC, duplicate suppression or missing gate data is a successful safety hold and failed activation canary. Do not edit verdicts. Test lifecycle as well as due date: a restored due date with terminal/closed state is not an armed queue item. After provider acceptance, inspect downstream ledger persistence and callback handling; an audit failure must not cause a duplicate retry.

## Rollback and acceptance

Disable the exact outbound lane first under approved rollback authority; verify effective flags, then back up failed-canary state. Delete only expressly authorized canary-created mutable rows after exact-reference assertions; preserve immutable ingress/audit receipts and unrelated historical data. Do not clear real contact suppression. Verify integrity, absence of the exact active canary record, ledger/provider outcomes, runtime health and scheduler state. If a provider attempt occurred, retain its delivery evidence rather than asserting zero sends from local cleanup.

Keep the lane disabled unless every required stage including reply routing and terminal delivery passed under the approved contract. Report not attempted versus accepted/queued versus delivered precisely. Documentation, local tests, live canary and activation are separate states.
