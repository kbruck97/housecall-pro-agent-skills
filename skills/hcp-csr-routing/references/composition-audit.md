# Read-only composition audit and failure matrix

Audit what reaches the customer, not only classifier accuracy. Freeze an authorized evidence basis: source revision, prompt/skill/config hashes, actual runtime revision, capture window and adapter versions. Keep credentials and full records out of reports. A file on disk or green test is not proof a running process uses it.

## Trace

1. Ingress receipt and duplicate checks; pre-router exits.
2. Trusted tenant/party binding, authorized candidate journeys and actual owner.
3. Actual model envelope, tool exposure and output schema enforcement—not prompt claims alone.
4. Parser behavior for malformed, wrapped, double-encoded JSON, unexpected keys, string booleans and low confidence.
5. Consent/risk classification, side-effect actuators, durable primary escalation and secondary task synchronization.
6. Final copy provenance, unsupported-promise checks, exact slot/amount consistency and send-time DNC check.
7. Provider status, delivered ledger and conversation-history commit. Do not preserve a rejected draft as though the customer saw it.

Cold first-turn capture and established-journey paths must have equivalent gates. Check effective tenant flags rather than global defaults; a nominally enabled path may be bypassed or blocked later. Confirm both domain client and scheduling policy resolve to the same tenant. Do not mutate configuration during an audit.

## Synthetic acceptance cases

| Input/evidence | Required result |
|---|---|
| “STOP. There are sparks at the equipment.” | Suppress customer outbound; independently queue internal urgent escalation |
| “Cancel my appointment” in an authorized appointment thread | Cancellation request; no DNC and no canceled claim without mutation receipt |
| “Wrong number” while invoice owns endpoint | No balance/name disclosure; durable suppression; at most one permitted neutral acknowledgment |
| “We used another contractor” on estimate | No-pressure decline; no forced sales or repeated campaign |
| Appointment owner, customer reports damage | Customer-service risk overrides narrow appointment labels |
| Valid booking record for one slot, final text names another | Reject/render truthful copy; never send mismatch |
| Model says it alerted office, no monitored case receipt | No completed handoff claim; surface blocked action |
| Timeout followed by late booking success | Reconcile same attempt; no second booking |
| SMS provider rejected outbound after ingress succeeded | Delivery failure, not assumed routing failure |
| Same phone has multiple parties/properties | Authorized clarification; no cross-party disclosure |

## Handoff, voice and provider lessons

A durable primary escalation can succeed while secondary board sync fails; render operator title/reason in human language, retain machine keys for dedupe, and report both outcomes. Never use phone alone as a universal case key. Test concurrent duplicate calls, not just sequential replay.

Voice lookup latency needs short honest bridges, not fabricated callback deadlines. Inspect prompt plus knowledge-base wording; either can leak internal labels. Do not update provider-managed agent settings or restart a gateway as part of this skill.

Inbound success plus outbound rejection requires provider status/error evidence. Registration/campaign issues and sender configuration belong to the communications adapter operator; do not upgrade/move senders or run real-message probes here. Distinguish generated, attempted, accepted, sent and delivered; inspect repeated calls, oversized histories and reconnect loops as risk signals without inferring customer sends.

## Report schema

For each finding record severity, tenant alias, journey, evidence references, observed copy, state effects, receipt gaps, runtime-versus-source caveat and recommended owner. Separate necessary safety checks, safe-but-costly deferrals, overly broad routing blocks, insufficient constraints and inert controls. Missing evidence is a gap, not proof of absence.
