# Source decisions and portability

The inventory identified one main/tree variant of hcp-trade-equipment. The read-time main file does not match the earlier inventory fingerprint; this draft uses the loaded current source rather than claiming byte-for-byte inventory provenance. The source was not modified by this packaging task. Owner authorization covers this distilled material despite the historical inventory drift; no byte-for-byte frozen-source claim is made. This editorial package uses that legacy umbrella as its base and its generic evidence-gate, address-scoping, API-write, taxonomy, customer-profile and failed-job-recovery references. It does not copy historical customer cases, raw evidence, scripts with private bindings or the full reference corpus.

## Conflicts resolved

- **Mode separation:** legacy strict installed-new creation remains a distinct lane. The specialist serviced-existing lane may recognize a documented appliance without make/model/serial. Neither lane silently replaces the other.
- **Completion:** historical references included payment-like statuses as completion. Payment alone is not completion; use the configured lifecycle contract and performed-work evidence.
- **Evidence absence:** zero notes and attachments is not a universal rejection when direct completed line descriptions carry adequate evidence. Generic labor-only lines remain insufficient for strict identity-backed installation creation.
- **Scope:** older references labeled some equipment query filters reliable. Later umbrella warnings supersede that assertion: validate every returned row and complete pagination.
- **Address:** nonzero identifier or missing billing flag alone is not property proof. Preserve null recovery only with an unambiguous same-customer service-property match; conflicting address fields block writes.
- **Taxonomy:** historical IDs and type-failure claims are neither repaired nor published as current truth. Functional model evidence, not single-zone versus multizone count, determines heat-pump classification. Lossy mappings need approval.
- **Writes:** replace automatic probe-create/delete and secret-handling recipes with adapter capability checks, explicit authorization, before-state guards, idempotency and exact readback. Cookie/CSRF behavior remains a private adapter concern.
- **Media:** replace authenticated third-party download patterns with credential-isolated downloads and redirect checks.
- **Identity:** registration forms are strong documentary evidence, not infallible identity truth. A conflicting legible target-unit plate controls model/serial; installation dates and warranty associations need their own corroboration.
- **Permissions:** account tags, procurement, production replay and publication remain separately authorized workflows, not incidental equipment actions.
