# Editorial source decisions

## Base selection

The source inventory reports one main/tree variant for hcp-equipment-nameplate-extraction. The entire source main file was read, including its accumulated exceptions, and its content hash matched the inventory. The inventory report and manifest supplied privacy and portability constraints. The historical case-reference corpus was not copied or repackaged.

## Selected reusable references

Source filenames below are provenance labels, not links to external or unbundled files:

- `completed-maintenance-worksheet-evidence.md`: retained unit-specific worksheets as possible serviced-existing/profile evidence, with explicit worksheet provenance and null install date. They remain ineligible as physical nameplates in strict mode.
- `product-brochure-vs-installed-unit-nameplate.md`: retained the distinction between generic product-family literature and independent installed-unit identity; replaced manufacturer/model/capacity examples with invented fixtures. Brochures cannot establish serial or property presence.

Both reference contents matched private inventory hashes. Source locations, historical filenames carrying identities, customer evidence, and record identifiers are deliberately absent from this package.

## Conflicts resolved explicitly

- The source alternates between accepting and rejecting cartons. The default is strict physical plate-only; carton-enabled identity requires explicit permission and target binding. A carton does not prove installation.
- The source mixes exact legal-manufacturer transcription with normalized consumer-brand exceptions. The draft uses explicit exact versus normalized policies and separates printed manufacturer from brand rather than preserving inconsistent case exceptions.
- The source alternates between all-unknown verdicts and partial fields. The draft keeps field-level observations and defines an explicit caller projection; partial extraction is not silently full confirmation.
- Same-label machine-readable codes can corroborate but cannot automatically fill unreadable human text under strict human-readable mode.
- Retained originals, orientation-aware cropping, glare/one-character uncertainty, sibling isolation, component selection, explicit model/serial rows and source deduplication.
- Removed session-file hunting, cross-tenant cookie probing, raw-header recovery, private hostnames, local paths, hardcoded auth helpers, and mandatory alpha/React access. Private collection remains opt-in and separately configured.
- Replaced repeated case anecdotes with synthetic acceptance cases and portable receipt schemas. No existing record values are promoted to evidence.

No external APIs, image engines, or private runtime adapters were exercised to author this package. The owner authorized this included material for MIT release; the full case corpus and neighboring packages are excluded from that grant. See [package validation](package-validation.md) for editorial checks, which are not live OCR/API certification.
