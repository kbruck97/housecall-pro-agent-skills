# Offline contract helpers and validation scope

`scripts/contracts.py` is pure logic, not a live API client. It validates declared ID format without repair; distinguishes Token/Bearer; checks company/customer/property; requires complete normalized page envelopes; chooses endpoint-specific pagination parameter; interprets epoch reset; sums split invoice allocations; distinguishes equipment modes; evaluates synthetic authorization/readback state; rejects credentialed attachment contexts/automatic redirects; verifies timestamped HMAC over exact bytes; gates normalized consent/ownership state and a small set of claims on typed receipts; and counts paired-store verified record writes without claiming physical-unit completion.

Adapters must translate their actual schema into these contracts. The page helper deliberately raises on duplicate/unstable totals; it does not fetch pages or offer snapshot isolation. Empty collections normalize to one successful page with total_pages=1 and total_items=0, while raw provider metadata can differ. Scope checks require adapters to obtain trustworthy company binding when source rows omit company fields; never fill it from customer prose. Equipment classification is only a candidate gate, not a complete evidence adjudicator. HMAC helper does not parse vendor headers, store dedupe state or implement tenant routing. Attachment validation does not implement DNS/IP/SSRF protection or perform downloads. Receipt gates are not natural-language promise/consent classifiers.

`validate.py` requires the root maintenance adapter (`AGENTS.md`) alongside the other distribution roots and checks MIT license text and skill license metadata, required simple frontmatter, unique names, package-local relative links, all required skills, source-family/instance/variant totals, capability names/statuses/official URLs, ledger-copy consistency, Python syntax/standard-library dependencies, JSON parsing and common privacy patterns. It does not fetch URLs, prove licensing, perform full semantic API review or recognize all PII. Required capability/status changes must be deliberately reviewed in both schema and ledger.

`tests/test_session_guidance.py` checks API-first instructions, discoverability and byte-identical standalone workflow copies, including negative fixtures for missing/drifted references. The validator enforces those copy boundaries. These are documentation regressions, not executed login, CSRF, host allowlist or session-security tests; no live session adapter is added.

`tests/test_offline.py` builds only synthetic fixtures and temporary copies. Invalid fixtures demonstrate detection of broken links, missing frontmatter, duplicate skill identity, private paths, private-key markers, absent dependencies, coverage holes, symlinks and malicious archive members. Contract tests cover ignored filters, nested/partial/repeated pages, billing-only/zero addresses, split allocations, installed-versus-serviced mode, stale/unapproved mutations, ambiguous responses, cross-property readback, third-party download isolation, raw-byte HMAC/timestamp changes, claimed-versus-reconciled payment and booking-versus-handoff receipts. Packaging tests build twice, compare hashes, stage real bytes and revalidate them.

`mutation_verdict` accepts a dictionary plan with nonblank string company/customer/property/target and intent identities and a nonblank before digest. These are opaque adapter-normalized tokens, not a universal HCP ID grammar; the known invalid property sentinel `"0"` is blocked, as are falsey/non-string IDs. The adapter must additionally validate its actual endpoint-specific ID rules and trustworthy scope binding. `approved_operations` must be a nonempty list, tuple, set or frozenset containing only nonblank strings. Approval uses exact string membership, never substring matching or coercion. Missing receipt (`None`) means awaiting execution; malformed receipts are blocked. Exact scoped readback and expected-field agreement remain required for verification. Expected values and their corresponding readback fields use recursive JSON-type-aware equality: booleans never equal numbers, integers and floats remain distinct (1 does not equal 1.0), arrays are ordered, and nested objects require identical keys but ignore key order. Finite floats compare by numeric value within their type, so signed zero is equal. Only exact built-in null/bool/int/float/string/list/dict representations with string object keys are accepted; nonfinite numbers, custom types, tuples/sets/bytes and cyclic or excessively deep containers fail closed. Invalid expected values block the plan before execution; invalid or mismatching compared readback values remain unverified. Extra top-level readback fields are outside the expected-field comparison. Adapters must perform any approved numeric normalization explicitly before constructing the plan/readback; the helper never coerces values.

Happy-call documentation tests preserve the configured-attempt eligibility, final terminal status/outcome and cleared/neutralized due-date assertions and explicit negative regression scenarios. They check the distributed contract text, not an implemented scanner/runner: no such runtime is shipped here. An integrating adapter must execute the full state-fed round trip described in that skill, including premature-cap and stale-final-due-date failures, against its own synthetic persistence/sender harness.

These tests are engineering contracts, not a claim of full workflow automation. No network-enabled integration tests are supplied. Do not substitute green offline tests for a separately authorized sandbox integration test and exact-target readback.
